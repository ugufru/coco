CoCo Renovation — Roadmap

Reset 2026-06-16. The previous roadmap had grown stale: its Phase 1 demo audit (issues 421-444) is done, kernel 1.2 shipped (the async sound engine), and the bulk of what was filed as "open" turned out to be an accumulated wishlist — ideas logged early and never pruned, which made the backlog look far heavier and more committed than it was. This version keeps only genuinely-live work, honestly prioritized, and parks the rest in an explicit Icebox (see bottom) rather than leaving it masquerading as planned work.

Where things stand (2026-10-26): a cross-developed Forth (kernel + fc.py) with ROM and all-RAM build profiles; a complete 13-chapter tutorial; ~20 demos; an interactive ITC-threading tutorial; FujiNet/clock live on real hardware; a Claude Code terminal over the Becker port; a disk library that reads DECB files without Disk BASIC. Since October the sound side has grown to every chip the CoCo Zero carries: SN76489 (GameMaster) with a song player and VGM playback, the AY-3-8910 (CoCo PSG and Symphony-12), and the Orchestra-90, shown side by side in src/sound-tour. Every library is in reference.html. Released as v1.2.

For per-issue detail, see issues.jsonl (statuses: open, in-progress, done, icebox, closed), browsable as issues.html. What to do next, in order and with reasons, is roadmap.jsonl (shown at the top of issues.html): this file is the shape of the work, that one is the queue.

North star: on-device, self-hosting Forth (decided 2026-07-19)

This section previously described the direction as an open fork. It is not open. See #551, which is the epic.

The CoCo compiles on itself. The COCO_RENOVATION.md vision, program the machine on the machine: today everything is cross-compiled from a laptop via fc.py, and the CoCo runs pre-compiled threads but cannot compile on itself. Forth is natively self-hosting, so the path is an on-device interpreter and compiler rather than a separate 6809 assembler.

#551 carries the settled design: headerless ITC threads stay byte-identical to cross-compiled images with names in a detached .sym sidecar; symbols are RAM-resident during a session and persisted to the filesystem at session boundaries; the live dictionary is the working artifact and source is stored per word; the editor is a definition editor, not a file editor; an on-device postfix 6809 assembler is critical, and its indexed-addressing postbyte encoder is the risk-carrying nugget. The first spike is that encoder, proved by diffing on-device output against lwasm for the same instructions.

Sub-epics get filed as #551 starts. Track 3 below is its seed, and remains worth building on its own terms.
